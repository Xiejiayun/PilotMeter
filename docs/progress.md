## Windows EXE 分发

`preview.5` 按用户需求增加 Windows x64 单文件 EXE，内置校验过的 Node 24.14.0 和锁定的生产依赖，无需用户安装 Node/npm。无参数启动后台服务并打开页面；CLI、独立账本与可恢复 statusline 继续可用。

本机 122 项 Node 测试、22 项 Chromium 测试、7 组真实 npm 安装验收及 13 组实际 EXE 验收通过。EXE 验收使用 PATH 无 Node/npm 的隔离环境，覆盖并发首次启动、后台输出结束、采集持久化、原生参数/stdio、移动 EXE 后的 statusline 和缓存篡改拒绝；本机 TTY 的 `watch` 退出与无参数打开页面另外实测。三平台 CI 继续运行，Windows job 新增实际 EXE 构建、验收和资产上传。详细范围及 `.cmd` 参数边界见 [Windows EXE 指南](windows-exe.md)。

该分发仍为未签名预览版；EXE 可直接运行不代表真实订阅或官方额度已通过对账。

## 多账号登录与个人额度

`preview.6` 补齐页面中直接登录 GitHub 的入口，支持添加不同账号、选择当前账号、重新登录、取消或重试设备授权，以及从 PilotMeter 移除账号。应用提供固定版本的官方 Copilot CLI，账号使用独立目录；确认身份后保存账号列表和当前选择，OAuth 授权材料由官方 CLI 保存。登录失败或尚未完成授权不会当作已连接账号。

个人 Copilot 当前周期额度放在页面上方，独立于所选 UTC 月份的本机记录和组织账单。上游提供的百分比按原含义显示；单位未说明时保留未知状态，不推断 AI Credits。个人额度、管理员设置的用户上限与组织共享池不能互相替代，登录账号也不会自动取得组织账单读取权限或启用旧账单对账。

账号切换立即清空旧的额度、会话详情与预算输入，网络请求携带预期账号范围；迟到的旧响应不能回填到新账号。每个账号的采集上下文和自定义预算隔离，`account use none` 明确显示全部本机记录。记录按启动时的账号归类，页面切换不会更改正在运行的会话；在 Copilot 内换账号后，需要退出并从 PilotMeter 重新启动，不能将启动时检查宣称为全程身份验证。

已完成合成账号的管理器、官方 CLI 协议边界、本地 HTTP 多账号记录与预算隔离、CLI 命令路由和浏览器回归验证；桌面宽度及 320px 网页布局已检查。`account refresh` 默认同步当前个人账号，`--billing` 明确刷新独立账单。本地 195 项 Node 测试、33 项浏览器测试及 7 组实际 npm 安装验收通过；Windows EXE 验收及三平台结果以对应 PR 的检查记录和 Release 为准。

本机现已连接一个真实账号，并读取到聊天、代码补全和高级请求三类个人额度快照。官方页面逐项比对、第二个真实账号的完整切换及会话对账尚未验证。记录中不包含私有账号、组织名或实际用量。

## 桌面挂件与独立主窗口

`preview.7` 将 Windows EXE 的默认入口改为原生桌面挂件，点击后打开原生 WinForms 主窗口，没有 WebView 或内嵌网页依赖。关闭主窗口保留挂件，隐藏后可从托盘恢复；重复启动按数据目录唤回已有实例。退出挂件保留后台采集，升级前需要先退出旧挂件再停止旧服务。`desktop --open` 可直接唤起独立主窗口；交互式 PowerShell 的 EXE `run`/`watch` 使用 `Start-Process -NoNewWindow -Wait` 保持终端输入归属。

挂件只读取经过服务身份核对的摘要，未登录、未知用量、同步失败、过期和离线均有明确状态。默认突出高级请求类别，聊天和代码补全等收进其他额度；没有高级请求时，只有唯一有限类别可以成为默认主指标，否则由用户明确选择。不同类别不相加，单位未明确的原始数量隐藏，过去的重置日期不作为下次重置。原生主窗口支持账号选择、添加、重新登录、移除、刷新及设备授权取消/重试，只访问已验证的 loopback API，修改请求绑定实例身份及 CSRF；GitHub 官方设备授权页由系统浏览器打开。

当前纯原生修订已通过 219 项完整 Node 回归、36 项浏览器回归、194 项原生检查和 7 组实际 npm 安装验收。原生检查覆盖参数、路径、DTO 和真实 loopback API；实际 EXE 与三平台 CI 的最终产物结果见对应 PR 检查记录及 Release，不以旧版产物代替本轮验收。当前 GUI EXE 的 `watch` 已在本机 TTY 中验证 `q` 和 Ctrl+C 正常退出。

原生窗口交互与视觉验收受工具错误阻挡：重新选择窗口后，激活操作仍返回 `GetCursorPos: Access is denied (0x80070005)`。点击、拖动、托盘恢复和原生布局尚未登记为通过，多屏 DPI、断屏恢复及干净系统也待实际验收。详细范围见 [Windows EXE 指南](windows-exe.md)；合成额度、网页截图和无窗口测试不记为真实桌面交互或账单验收。

- 当前原生主窗口与挂件的实际交互、视觉布局、跨屏 DPI 和断屏恢复验收。
