# PilotMeter 0.1.0-preview.16

修复点击同步后仍读取 CLI 持久化账号缓存、用量落后于 VS Code 的问题。preview.14 的重启查询进程和 preview.15 的小数精度修复，均未绕过这一层缓存。

- 显式调用官方 CLI 的账号元数据刷新能力，直接采用返回的额度快照，不再混入普通账号接口的旧数据。
- 刷新前后核对所选账号身份。临时空会话不发送模型消息、不授权工具，禁用项目配置发现，完成后删除；凭据仍由官方 CLI 管理。
- 保留额度小数精度，缺少可靠数量时显示未知，不从舍入百分比反算已用量。刷新失败时保留旧数据并显示失败状态。
- 分别显示来源数据时间与本次读取时间。来源时间未知或超过 5 分钟的数据不显示为已同步。
- 重置时间采用实际额度重置字段，不再把快照生成时间误当作重置时间。

固定适配 Copilot CLI 1.0.88 的实验性接口。已在本机真实账号验证：强制刷新返回的用量与用户提供的 VS Code 截图一致，普通账号接口在同一进程中仍返回旧快照。此验证不代表组织共享账单、所有订阅或未来时点均已对账；GitHub 用量入账仍可能延迟。

## 本地验证

308 项 Node 测试、96 项 Chromium 测试、7 组 npm 安装验收和 17 组实际 EXE 验收通过，分发文件的 SHA-256 校验通过。Windows 验收包括 739 项原生契约、15,837 项布局断言、101 项登录、16 项恢复及 53 项真实 WebView2 检查。零透明度 WebView2 窗口未取得有效截图；DOM、CSS、桥接和 Chromium 画面验证通过。

首次 Node 与浏览器并行运行时，一项状态栏读取测试触发 250 毫秒时限；移除并行负载后完整 Node 套件通过，生产超时未改动。

## 使用与升级

使用 `PilotMeter-0.1.0-preview.16-win-x64.exe`。先结束采集中的 Copilot 会话，从旧宠物或托盘菜单退出桌面程序，再执行旧版 EXE 的 `stop` 命令停止后台服务，最后启动新 EXE。只替换文件不会更新正在运行的进程。

账户、账本和宠物设置保留在原数据目录。使用自定义数据目录时，停止和启动命令应带上相同的 `--data-dir`。
