## 能力边界

- Windows GUI 子系统避免双击弹出控制台，但交互式 PowerShell 可能立即返回提示符。交互式 `run`/`watch` 使用 `Start-Process -NoNewWindow -Wait`；`preview.5` 曾在本机 TTY 验证 `watch` 的 q 和 Ctrl+C，当前 GUI 子系统版本的终端交互仍需验收。桌面单实例以数据目录为界，升级前必须先退出旧挂件，再停止旧服务。
- 早期实时桌面检查曾因激活操作返回 `GetCursorPos: Access is denied (0x80070005)` 受阻。当前布局与登录检查使用隔离的零透明度原生窗体，不控制用户正在使用的窗口。它们可以验证控件尺寸、真实按钮事件和模态窗口生命周期；不能代替实际点击、拖动、托盘恢复、跨物理屏幕 DPI、断屏恢复和干净系统验收。

- `preview.6` 的登录界面支持 `https://github.com` 和 `https://<tenant>.ghe.com`。浏览器中已有的 GitHub 登录状态不会自动成为 PilotMeter 的已连接账号；必须完成官方设备授权，并由 CLI 返回实际身份。重新登录已有账号时身份不符会被拒绝。
- 个人 Copilot 额度只表示登录用户当前周期的上游快照，不随网页的本地月份选择变化。上游明确返回的百分比可单独展示；接口未说明单位时，主额度区域直接显示原始已用和总额，并明确标注“单位未确认”，同时保留可靠比例或额度状态。不能据类别名、字段名或比例推断为 AI Credits 或 Premium Requests，也不能据此验证本机 nano AIU 换算或组织共享池分母。仅有效未来日期可标为下次重置。
- 额度数量和百分比保留完整十进制数值，包括超过 JavaScript 安全整数范围的数量和高精度小数。千位分隔符只改善阅读，不改变数字；界面不使用四舍五入、科学计数法、K/M 缩写或 `<0.1%` 等阈值替代值。HTML 工作台的额度指标根据可用宽度排列，数值保持单行，极长数值可横向滚动查看；旧网页按可用宽度换行。详情与主额度区域保持相同精度。
- `account use` 选择后续启动采集和页面查看的账号。记录按启动时的账号归类，页面切换不会更改已经运行的采集上下文；这不是会话期间持续验证 OAuth 身份。在 Copilot 内切换账号后，请退出并从 PilotMeter 重新启动。`account use none` 显示全部本机记录，包含各账号和旧的未分账号记录；旧记录不会自动划给新登录账号。
- 选中 GitHub 登录账号时不显示旧的、未验证身份关联的组织账单，不启用该账号与旧账单的对账。`account refresh` 默认同步选中的个人额度，`account refresh --billing` 显式刷新独立账单主体；没有选中账号时保留原账单刷新行为。账号预算相互隔离，明细保留策略仍作用于整个数据目录。
- `init --statusline` 及恢复命令仍使用当前 shell 的 `COPILOT_HOME`，未设置时为普通 `~/.copilot`；不会自动跟随页面选中的受管账号。受管账号目录的状态栏尚未自动配置，可使用 `watch` 和页面查看用量。
- 不保存 prompt、response 等内容的承诺仅限 PilotMeter 计量账本。内置官方 Copilot CLI 会按自身设置保存账号目录中的会话历史和日志，可能包含对话内容，且不受账本的 `retention.days` 策略清理。
- `preview.4` 增加 24 小时待分类超时诊断。超时从首次采集时间计算，不从历史调用结束时间计算；仍保持 pending 并排除费用，真实祖先后到可重新判定，已有超时诊断保留。
- `preview.3` 对账入口通过显式证据验证全部来源、账户池、产品和月初至官方截止的半开范围；金额来自真实账本查询，证据不能覆盖金额。账本或快照变化、无法定位异常、清理影响和证据过期均阻止比较。工程测试使用合成数据，不构成真实账户核验。
- `preview.2` 增加显式 `retention.days` 策略，默认关闭。schema v2 升级前备份；清理原子提交并保留最小 trace 防重放标记，不恢复已清理历史。时间不明、跨阈值或冲突 trace 保守保留。
- 模型 chat 小计按贡献记录单独核实 CLI 版本，未知版本保留原始单位，异常或冲突记录列入未知，不能套用当月顶层调用的单位证据。
- Billing 403 有限流头时执行退避；普通权限错误保持暂停。重启后恢复失败快照及重试截止时间，不通过重启提前再次请求。

- 当前已核查的采集分类规则固定为 CLI `1.0.88`：`invoke_agent`，合法 server address/port，且祖先链不含其他 invoke_agent。未知版本或缺失祖先保持待分类。
- 组织、企业付费不能通过个人 endpoint 的空列表证明零用量；端点按显式主体选择。
- 测试 fixtures 均为人工合成，只用于验证解析、精度、幂等和边界，不冒充真实脱敏账单。
- 首版以启用采集后的本地记录为准。SDK 历史读取属于独立后续适配，不读取或恢复活动会话。
- JSONL 已验证格式为每行一个 OTLP traces `resourceSpans` envelope，原生 CLI file exporter 格式尚未取得真实样本。不能把本格式的合成测试算作原生文件兼容证据。
- `preview.6` 用固定官方 CLI 的实验性账号 RPC 读取个人额度，不依赖自动安装实验性 SDK。旧的 `account import-quota` 仍是独立的显式核验证据导入入口；组织文档中其他 SKU/单位组合暂为 unsupported，完整额度池覆盖不能从单一产品推断。
- npm 本地包验证与公开发布分开；未获得发布账号、包名归属和公开发布授权前不发布。

## 真实验收仍需的证据

1. 对已连接的真实账号完成身份、个人额度与官方页面的逐项比对；再完成第二个真实账号的添加、切换、重新登录和独立采集验收。
2. 具体组织或企业及有权限的专用只读凭据来源（不把 token 写入源码、命令参数或文档）。个人设备码登录不等于取得组织账单权限。
3. 同一 CLI 会话的普通请求、切模型和子代理场景：遥测顶层计量与 `/usage` 对照。
4. 官方页面与 quota 的月度池、单位、周期、分母和同池产品覆盖；共享池、管理员设置的用户上限和个人额度分别核实。
5. Windows Terminal 和 Copilot 状态栏分别测试链接、stdin、stdout、Ctrl+C。

这些门槛未通过时仍为预览版。单个真实账号的额度读取不等于官方页面对账，不能宣称真实多账号或组织全池对账已经完成验证。
