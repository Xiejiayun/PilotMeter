01 / DESIGN INTENT

先回答用户最关心的四件事

现在的界面缺少稳定的信息层级。大比例数字不能替代实际余量，未知单位不能靠名称猜测，登录后的模型权限也需要独立呈现。

01 / 层级

我正在看哪个账户？

账户与数据范围固定在页首；主额度突出显示，其他类别收进详情。

02 / 数量

总额多少，已经用了多少？

总额、已用、剩余同时可见；比例承担比较作用，不占据整页。

03 / 单位

这些数字到底代表什么？

只使用返回数据中已确认的单位；不确定时保留原始数值入口。

04 / 模型

这个账户能用哪些模型？

将模型权限独立列出，解释可用、组织禁用和待验证的区别。

阅读边界：这份报告定义拟实现的界面和数据规则。下方额度、模型、状态均为设计示例，不代表当前账户数据、真实订阅权限或已经完成的产品功能。
02 / INFORMATION ARCHITECTURE

轻量常驻，详情各有位置

挂件保留一个高频摘要。打开主窗口后，使用稳定的四页导航，让额度、模型、消费记录与账户管理各自承担清晰的职责。

总览的阅读顺序

当前账户与范围 → 额度总量 → 已用与剩余 → 数据更新时间 → 次要用量分类。把排查细节放在展开区，避免占据首屏。

切换账户后的行为

额度、模型和记录一起切换账户上下文。加载时显示目标账户名称；没有对应数据时呈现待同步，避免短暂混入上一账户数据。

03 / SHARED QUOTA

一个额度池，三个明确的数量

总览以当前账户选定的额度池为主。模型可能共享这一额度池，但模型列表不虚构各自的余额；计费倍率与资格只有在来源确认后才展示。

CURRENT ACCOUNT / SHARED POOL当前账户 · 已确认单位的共享额度池

已用 37.6%剩余 62.4%
20,000 总额 − 7,520 已用 = 12,480 剩余 · 同一范围、同一单位、同一额度池
组织付费的范围标记：组织或企业付费，不代表当前账户的返回值就是组织总池。账户获配额度与组织／企业月度账单需分别标注主体、周期和来源；只有范围确认后，才能展示组织总额度与对账结果。
  • 只有单位明确、固定总额有效且属于同一额度类别时，才计算绝对剩余量；采用精确十进制运算，不由百分比反推数量。
  • 超额时保留真实已用量，剩余显示为 0，并单独注明超出值；无限额显示“无固定上限”，不绘制误导性的百分比。
  • 多种额度类别并存时显示明确的当前类别；没有可靠主类别时让用户选择，不把不同单位合并成一个总数。
  • 组织／企业账单的月度预算与账户额度属于不同的数据视图；未完成真实对账前，明确标记“未对账”。
04 / MODEL ENTITLEMENTS

模型可见，权限有依据

登录成功只说明身份验证完成。模型是否可用，必须由实际返回的模型授权或组织策略信息支持；缺少足够证据时，保留“待验证”。

模型名称仅用于排版示意。Claude Sonnet 4.5、GPT-5 和 Gemini 2.5 Pro 不构成真实权益清单，也不代表准确的当前模型目录。下表状态同样为设计示例。

05 / NUMERIC INTEGRITY

数值透明，单位不猜

数量与单位一起构成事实。确认单位时提供精确数量；未确认时保留服务端给出的有效比例，并允许查看经过筛选的原始数值字段。

A / 单位已确认AI Credits · 示例
12,480 AI Credits 剩余已用 7,520 / 总额 20,000 AI Credits

数值旁始终可见单位。精确的总额、已用与剩余优先，比例提供辅助比较；长数字采用分组显示。

  • 如果返回比例缺失或无效，显示“比例未知”；不在单位与数据语义不明时静默推算。
  • 不同账户可能返回不同单位；切换时同步切换单位与来源。数量与比例不一致时保留来源事实并提示差异。
  • 有效的未来重置时间才显示倒计时；时间缺失或已经过期时，展示“重置时间待确认”。
06 / DATA STATES

没有数据，也要说清发生了什么

把同步状态与额度事实分开。缺失不等于零，失败不清空已知数据，旧快照也不能伪装成实时信息。

状态主窗口展示用户下一步
暂无数据数值显示“—”，解释尚未连接、尚未同步或来源未返回此字段。连接账户或立即同步；不能显示“剩余 0”。
同步中保留同一账户已有快照与更新时间；首次同步显示轻量占位。允许继续阅读；禁用重复同步请求，不阻塞整页。
同步失败显示失败原因和最后成功时间；旧值标为“上次成功数据”。重试；身份过期时重新授权，服务离线时检查服务。
旧快照显示“数据可能已过期”及快照时间。拟沿用超过 5 分钟的旧快照判定。主动同步；确认来源恢复后才移除过期标记。
范围待确认区分账户额度与组织账单；缺少范围或周期时不作跨来源比较。补充可验证的授权或数据来源，并完成官方页面核对。
状态信息同时使用文字＋颜色＋时间，避免仅靠颜色理解。
07 / DESKTOP WIDGET

桌面只留一个有用的摘要

挂件服务于短暂扫视：正在使用的账户、剩余量和数据状态。点击进入主窗口后，再获得额度构成、模型与使用记录。

示例内容，不代表当前挂件实装。

数量明确时显示余量，未知时显示比例

已确认单位的固定额度可显示“12,480 AI Credits 剩余”。单位待确认时切换为“剩余 62.4%”，并带上“单位待确认”；没有可信比例时显示“额度待同步”。

异常摘要保留可操作入口

等待：“待同步 · 点击查看”；失败：“同步失败 · 点击查看”；过期：“旧快照 · 待同步”；服务中断：“服务离线 · 点击查看”。已有数据也必须带上对应状态。

主点击打开总览；拖动区域与点击行为分开处理。右键菜单提供账户切换、同步与退出挂件。退出挂件和停止后台服务保持不同的明确操作。

08 / DESIGN SYSTEM

安静的底色，清楚的操作

浅灰绿画布托起白色内容区，深墨色承载信息，翡翠绿表达主操作与有效状态。暖琥珀仅用于待确认和提示。

画布#EDF1ED
主要文字#192B29
强调与操作#19745E
待确认提示#FCF2DF / #956115

尺寸与排版

主窗口建议约 1280 × 850，最小 880 × 640；主导航约 190 宽，挂件约 310 × 100，均为逻辑像素。圆角 8 / 12 / 16，间距采用 4 / 8 / 12 / 16 / 24 / 32。

字体采用 Segoe UI Variable → Segoe UI → Microsoft YaHei。正文建议 13–14 px，次要说明 11–12 px，关键数量 40–48 px；数字等宽对齐。

键盘与焦点

Tab 按视觉顺序移动焦点；Enter 激活按钮，Space 切换选项和展开区；导航支持方向键。弹窗打开后进入焦点，关闭后回到触发点。

焦点始终可见。Esc 关闭当前弹层，不误触停止服务。主窗口关闭后保留挂件，与现有生命周期一致。

布局与缩放

原生窗口使用弹性列宽、自动换行与必要的纵向滚动；不得截断额度单位。验证 100% / 125% / 150% / 200% DPI 和跨屏切换。

HTML 设计稿在窄屏折叠导航并堆叠内容，便于审阅。原生桌面仍遵守最小窗口尺寸；长模型名、错误说明和大数值都应换行。

09 / NATIVE IMPLEMENTATION

把这份提案落到原生控件

HTML 是离线审阅载体。后续界面沿用 Windows WinForms / .NET Framework 4.8，通过原生布局、绘制和辅助功能实现设计。

设计元素建议控件与层次实现要求
主窗口与导航Form + TableLayoutPanel + 导航按钮独立页面容器；切页保留账户上下文。布局、键盘与辅助功能优先于纯装饰。
额度与比例条Label + 轻量自绘进度控件数量与单位使用明确 DTO；文字可被读屏读取；绘制比例限制在有效范围内。
模型与用量记录DataGridView 或原生列表模型权限与额度数据分别映射；支持键盘选择、排序、长文本和空状态。
原始数值展开区展开按钮 + 只读字段容器只从 DTO 白名单取值；允许复制数值，不直接渲染完整服务端响应。
挂件与同步状态现有挂件窗体 + 共享状态投影使用与总览相同的账户、单位和过期规则；工作线程更新数据，UI 线程安全刷新。
已有基础 / 非本次新增

当前实现可沿用的能力

  • WinForms 原生主窗口、桌面挂件和本地服务。
  • 账户连接、总额／已用／剩余比例读取及部分同步状态展示。
  • 已确认单位与未知单位的区分，以及过期数据判定。

当前单位缺失时会隐藏已有数量，不代表接口没有返回数字；历史观测到的模型也不等于当前可用模型目录。

本报告提案 / 后续实现

仍需开发与验证的内容

  • 四页信息架构、明确的绝对剩余量和新版布局。
  • 基于真实权限来源的模型清单与组织策略状态。
  • 单位未知时的安全数值展开区、记录页和真实账单对账。

真实模型资格、组织总额度与可用数据源需要单独验证。

验证边界：本 HTML 的可读性与交互检查，不能代替原生窗口的点击、拖动、托盘和 DPI 验收，也不能代替真实账户、官方页面及组织／企业账单对账。
  • 用固定示例验证总额、已用、剩余和百分比关系；覆盖未知单位、无限额和超额。
  • 模拟缺失、同步、失败与过期状态，确认账户切换不会展示错误主体的数据。
  • 核对模型授权与策略来源，确认登录成功不会把模型自动标为“可用”。
  • 实际操作原生窗口、挂件和托盘，验证键盘、长文本、多屏与不同 DPI。
  • 使用组织或企业付费账户完成官方来源核对；真实账户资料不进入代码、测试夹具或设计文档。
